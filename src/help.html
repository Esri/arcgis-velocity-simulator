ArcGIS Velocity Simulator Help

Overview

Cross-platform desktop application for simulating data streams from CSV files over TCP, UDP, HTTP/HTTPS, WebSocket, gRPC, and XMPP protocols. Every protocol can run as a client or as a server, so the Simulator can either push data to a receiver such as an ArcGIS Velocity feed or an ArcGIS GeoEvent Server connector, or host an endpoint the receiver connects to. Features gesture and voice controls for hands-free operation.

The connection panel holds what every connection needs, in order: File, a compact Setup toolbar (Preset and Settings), Mode, Connection (host and port), the replay rate, and the connection actions. Pick a paired Simulator and Logger preset to pre-fill every connection field for a local test, then review the values, select a file, and select Connect and Play.

Everything specific to the selected protocol is edited in the dedicated, resizable Protocol Settings window (Cmd+Shift+P / Ctrl+Shift+P), grouped into Basics, Security, Advanced, and a read-only Summary. The Settings button shows a compact count when values differ from their defaults. Edits apply to the next connection; nothing is sent until you select Connect. Done and Esc keep the edits, Revert changes restores the values the window opened with, and Reset to preset reapplies a modified preset.

Open the Summary tab in Protocol Settings to view the full read-only Connection Summary, including the effective URL. The panel otherwise stays compact; only a genuine warning, such as disabled certificate verification, appears beneath the Setup toolbar. A password is never shown: it is reported only as Set (hidden), Empty, or Not set.

Quick Start

  1. Select CSV file
  2. Optionally choose a Preset to pre-fill a paired local Simulator and Logger test
  3. Choose protocol mode (TCP/UDP/HTTP/WebSocket/gRPC/XMPP Server/Client). Selecting XMPP uses port 5222 and the Client role unless you change them.
  4. Set IP address and port
  5. For HTTP, WebSocket, gRPC, or XMPP: select Settings to open Protocol Settings with the protocol-specific controls (format, TLS, paths, headers, or XMPP account and conversation settings)
  6. Select Summary to review every setting; any warning also remains visible beneath the Setup toolbar
  7. Configure streaming rate
  8. Connect and Play

Connection Modes

  • TCP Server: Listen for incoming TCP connections from clients
  • TCP Client: Connect to a remote TCP server
  • UDP Server: Listen for incoming UDP datagrams
  • UDP Client: Send UDP datagrams to a remote server
  • HTTP Client: Send data via HTTP/HTTPS POST requests to a remote endpoint (e.g. an ArcGIS Velocity HTTP Receiver feed). Supports JSON, Delimited (CSV), Esri JSON, GeoJSON, and XML formats.
  • HTTP Server: Start a local HTTP/HTTPS server that accepts POST requests from clients. Use for testing or when the Velocity HTTP Receiver connects to this app.
  • WebSocket Client: Connect to a remote WebSocket server (ws:// or wss://) and send streaming data. Supports JSON, Delimited (CSV), Esri JSON, GeoJSON, and XML formats. Can send a subscription message on connect and optionally ignore the first message.
  • WebSocket Server: Start a local WebSocket server (ws:// or wss://) that accepts incoming connections and broadcasts data to all connected clients. Supports the same 5 formats as the WebSocket client.
  • gRPC Client: Connect to a remote gRPC server using HTTP/2. Supports Protobuf, Kryo, and Text serialization with client-streaming or unary RPCs.
  • gRPC Server: Start a local gRPC server that accepts incoming RPC calls from clients.
  • XMPP Client: Sign in to an XMPP server (RFC 6120) and publish each line as a one-to-one chat message to up to 20 destination JIDs, or as a groupchat message in a Multi-User Chat room. Use when the receiver is an ArcGIS Velocity XMPP feed, an ArcGIS GeoEvent Server XMPP connector, or any standards-compliant XMPP server. This is the default role when XMPP is selected.
  • XMPP Server: Host a local XMPP client-to-server endpoint that a receiver signs in to. The Simulator publishes each line from its own automatic application identity to every signed-in account, or into a room it occupies. The server binds a loopback address unless Allow remote is enabled.

Connection Presets

A preset only pre-fills editable connection fields. It never connects, never starts playback, never selects a file, never saves a password, and never changes the startup defaults. Every field stays editable, and each preset resets the fields it does not use so results are repeatable.

Custom is the default and keeps your current values. Editing any populated field after applying a preset shows Custom (modified) with a small Modified badge; your edit is kept and re-selecting the preset restores its values.

The same twelve identifiers and labels exist in the ArcGIS Velocity Logger with the roles inverted, so both applications are configured by picking the entry with the same name. Labels naming Logger Server select a Simulator client mode; labels naming Simulator Server select a Simulator server mode.

  • Local TCP / Local UDP: 127.0.0.1:5565.
  • Local gRPC: 127.0.0.1:5565, Text serialization, Client Streaming, TLS off.
  • Local HTTP: 127.0.0.1:8080, Delimited (CSV), path /, TLS off.
  • Local WebSocket: 127.0.0.1:8080, Delimited (CSV), path /, TLS off, no subscription message, first message kept.
  • Local XMPP: 127.0.0.1:5222, domain localhost, Direct, Required STARTTLS. The client variant signs in as simulator with an intentionally empty password, publishes to velocity-logger@localhost, and turns Allow unverified on; the server variant accepts external account velocity-logger with an intentionally empty password, keeps Allow remote off, and sends to every signed-in stream.

HTTP Settings

When HTTP is selected, choose HTTP Settings… below the Connection row, or press Cmd+Shift+P / Ctrl+Shift+P, to open Protocol Settings. Basics holds Format and HTTP path; Security holds the TLS and certificate controls. HTTP has no Advanced section.

  • Format: Controls the Content-Type header — JSON (application/json), Delimited/CSV (text/plain), Esri JSON (application/json), GeoJSON (application/geo+json), or XML (application/xml). Must match the format configured in the ArcGIS Velocity HTTP Receiver feed.
  • Use TLS: Enable HTTPS (port 8443 by default). Uses the OS certificate store automatically in client mode. Server mode requires a certificate and key.
  • CA cert: Custom CA certificate file (PEM). Leave empty to use the OS certificate store. Only needed for enterprise or self-signed CAs.
  • TLS cert: Client or server certificate file (PEM). Required for server-mode TLS; only needed in client mode for mutual TLS (mTLS).
  • TLS key: Private key file (PEM). Required for server-mode TLS and client-side mTLS.
  • Allow unverified: Client-only warning checkbox shown when TLS is enabled. Accepts an unverified HTTPS server certificate for any host, not only localhost. Traffic stays encrypted, but the server identity is not checked. Off by default.
  • HTTP path: URL path appended after host:port (default /). In server mode, only POST requests matching this path are accepted. In client mode, this path is used in outgoing POST URLs. Set to the Velocity feed's system-generated path (e.g. /receiver/feed-id) when connecting to a real endpoint.

WebSocket Settings

When WebSocket is selected, choose WebSocket Settings… below the Connection row, or press Cmd+Shift+P / Ctrl+Shift+P, to open Protocol Settings. Basics holds Format and WS path; Security holds the TLS and certificate controls; Advanced holds the subscription message, Ignore first message, and the custom headers.

  • Format: Controls the data format — JSON (application/json), Delimited/CSV (text/plain), Esri JSON (application/json), GeoJSON (application/geo+json), or XML (application/xml).
  • Use TLS: Enable WSS (WebSocket Secure, port 8443 by default). Uses the OS certificate store automatically in client mode. Server mode requires a certificate and key.
  • CA cert: Custom CA certificate file (PEM). Leave empty to use the OS certificate store. Only needed for enterprise or self-signed CAs.
  • TLS cert: Client or server certificate file (PEM). Required for server-mode TLS; only needed in client mode for mutual TLS (mTLS).
  • TLS key: Private key file (PEM). Required for server-mode TLS and client-side mTLS.
  • Allow unverified: Client-only warning checkbox shown when TLS is enabled. Accepts an unverified WSS server certificate for any host, not only localhost. Traffic stays encrypted, but the server identity is not checked. Off by default.
  • WS path: URL path appended after host:port (default /). In server mode, only WebSocket upgrade requests matching this path are accepted. In client mode, this path is used in the outgoing connection URL.
  • Subscription message: Optional text message sent to the server immediately after the WebSocket connection is established. Useful for subscribing to a specific data feed or channel.
  • Ignore first message: When enabled, the first message received after connecting is silently discarded. Useful when the server sends an initial handshake or acknowledgement message.
  • Custom headers: Optional JSON object of custom HTTP headers to include in the WebSocket upgrade request (client mode only). Example: {"Authorization": "Bearer token123"}.

gRPC Settings

When gRPC is selected, choose gRPC Settings… below the Connection row, or press Cmd+Shift+P / Ctrl+Shift+P, to open Protocol Settings. Basics holds Serialization, RPC Type, and the header path; Security holds the TLS and certificate controls. gRPC has no Advanced section.

  • Serialization: Protobuf (default, external GrpcFeed protocol), Kryo (internal GrpcFeatureService, binary), or Text (internal GrpcFeatureService, UTF-8 CSV).
  • RPC Type: Client Streaming (persistent stream, higher throughput) or Unary (individual request/response per message).
  • Use TLS: Enable TLS for the gRPC connection. Uses the OS certificate store automatically.
  • Header Path Key / Path: Custom gRPC metadata header for endpoint routing (client mode only).
  • Allow unverified: Client-only warning checkbox shown when TLS is enabled. Accepts an unverified gRPC server certificate for any host, not only localhost. Traffic stays encrypted, but the server identity is not checked. Off by default.

XMPP Settings

When XMPP is selected, choose XMPP Settings… below the Connection row, or press Cmd+Shift+P / Ctrl+Shift+P, to open Protocol Settings. Basics holds Conversation, Domain, the account fields, and the destination or room; Security holds STARTTLS, the certificate paths, Allow unverified, and Allow remote; Advanced holds the timing values. Only the controls that apply to the selected role and conversation type are shown.

  • Conversation: Direct (default) delivers each line as a one-to-one chat message to every destination JID. Room (MUC) broadcasts each line as an XEP-0045 groupchat message; every occupant receives it and the room echoes the message back to the sender.
  • Domain: The XMPP domain served (server role) or authenticated against (client role). It is independent of the host in the Connection row, so a client can connect to an IP address while authenticating against the real domain. Rooms live under conference.<domain>.
  • STARTTLS: Required (default) refuses to send a credential until the stream is encrypted. Preferred upgrades when the peer offers it. Disabled does not require encryption — the built-in server stops advertising STARTTLS, and as a client the Simulator still accepts an upgrade a third-party server insists on, so Disabled means "do not require TLS", not "refuse TLS".
  • CA cert (client): Custom CA certificate file (PEM) used to verify the server certificate. Leave empty to use the OS certificate store.
  • Validation: No required field is hidden. If a connection attempt fails validation while Protocol Settings is closed, it opens on the section holding the offending control, reveals and focuses it, and names the problem in a banner as well as in the status log.
  • Allow unverified (client): Skips certificate verification. The bypass applies to any host, not only localhost. STARTTLS still encrypts the stream, but the server identity is not checked. Off by default and styled as a warning.
  • TLS cert / TLS key (server): Server certificate and matching private key (PEM) presented during STARTTLS. Leave both empty to use an automatic self-signed certificate.
  • Allow remote (server): Allows the server to bind a non-loopback address such as 0.0.0.0. Left off, nothing outside this machine can sign in.
  • Username / Password (client): The account to sign in with. Enter a local part such as simulator, or a full bare JID such as simulator@example.com, which overrides the Domain field. A password may be present but empty for a local test with no shared secret; the username remains required.
  • Resource (client): Resource part requested at bind time, which distinguishes this stream from other sessions of the same account.
  • Account / Acct pwd (server): The required external account the built-in server accepts, alongside the automatic simulator application identity. Give it to the receiver you want to sign in. The account password may be present but empty; the account name remains required.
  • Destination (Direct): Bare destination JIDs in user@domain form with no resource part, up to 20 separated by commas. In server mode, leave empty to publish to every signed-in account.
  • Room / Nickname / Room pwd (Room): The room to publish into, the nickname to use inside it, and an optional room password. A bare room name is qualified with the conversation sub-domain of the Domain field. In server mode the room password also protects the room against every other occupant.
  • Timeouts ms: Connect timeout (default 30000) for stream negotiation, authentication and resource binding, and reply timeout (default 15000) for requests that expect an answer such as a room entry confirmation or a ping result. Both must be positive whole numbers of milliseconds; there is no wait-forever value.
  • Ping ms (client): XEP-0199 keepalive interval on an otherwise idle stream (default 60000). Must be a positive whole number; the keepalive cannot be switched off.
  • Reconnect ms (client): Delay before the automatic reconnect after a dropped stream (default 60000). A reconnect re-binds the resource and re-joins the room; stream resumption is not implemented, so nothing sent while the stream was down is replayed. Must be a positive whole number; automatic reconnect cannot be switched off.
  • Copy Client Settings (server): Copies the settings a receiver needs as canonical option=value lines — ip, port, xmppDomain, xmppTlsPolicy, xmppAllowUnverifiedTls, xmppUsername, the destination or room, and the xmppConnectTimeoutMs, xmppReplyTimeoutMs, xmppPingIntervalMs and xmppReconnectDelayMs timings — so the block can be pasted straight into a command line. The network host is the shared ip option, which is separate from xmppDomain. The account password is left out unless Include password is checked.

Minimal local UX test with Logger

Select the preset Local XMPP — Logger Server / Simulator Client in the Simulator and the entry with the same name in the Logger, then select Connect in the Logger and Connect and Play in the Simulator.

The equivalent command line keeps the XMPP defaults for port 5222, domain localhost, Direct conversation, and Required STARTTLS, and leaves both passwords empty. Start the Logger first.

Terminal 1 — Logger:

npm start -- protocol=xmpp mode=server ip=127.0.0.1 xmppExternalUsername=simulator xmppExternalPassword=

Terminal 2 — Simulator:

npm start -- filename=/Users/hano4470/Backup/data/faa.csv protocol=xmpp mode=client ip=127.0.0.1 xmppUsername=simulator xmppPassword= xmppDestination=velocity-logger@localhost xmppAllowUnverifiedTls=true

Select Connect in the Logger, then Connect and Play in the Simulator. xmppAllowUnverifiedTls=true is an explicit opt-in that accepts the Logger's automatic self-signed certificate while STARTTLS still encrypts the stream. It applies to any host, so leave it off outside local testing.

SASL. A secure stream uses the server's preferred mechanism, normally SCRAM-SHA-1. An unsecure stream uses a non-PLAIN mechanism, and falls back to PLAIN only when the STARTTLS policy is deliberately set to Disabled. Both PLAIN and SCRAM-SHA-1 accept an empty password.

Limits and behavior. Message bodies are capped at 65,536 UTF-8 bytes and are rejected rather than truncated, so a replay never silently loses data. Destination and account JIDs must be bare. Only type=chat is treated as inbound direct data; anything else is refused rather than replayed. Rooms keep no history, so a receiver only sees what is published after it enters. Stream management (XEP-0198) is negotiated and acknowledged, but resumption is not implemented: a dropped stream reconnects as a brand new session that re-binds its resource and re-joins its room.

Security. With STARTTLS set to Required the client aborts before SASL when the peer does not offer an encrypted stream, so no credential is ever sent in the clear. With Preferred the status bar and TLS badge report the actual state of this connection, never the peer's advertised capability. The external account cannot canonically collide with the automatic velocity-simulator identity, the server certificate and private key must be supplied as a pair, and password whitespace is significant everywhere — the UI, the command line, and launch configuration files all keep it exactly as typed. The certificate verification bypass is explicit, off by default, and applies to any host, not only localhost.

Velocity Login & Feed Picker (🔑)

Click the 🔑 button in the toolbar to sign in to your ArcGIS Velocity organization and browse available feeds. This allows you to auto-populate connection settings without manual configuration.

  • Portal URL: Your ArcGIS Online or Enterprise portal URL (default: https://velocitydemo.maps.arcgis.com).
  • Username / Password: ArcGIS account credentials. A token is generated and automatically refreshed before expiry.
  • OAuth 2.0: Alternative tab for OAuth client credentials (Client ID + Secret). Currently supported only for HTTP Poller feeds.
  • My Feeds / ORG Feeds: Segmented toggle to switch scope. "ORG Feeds" is the default and adds view=admin to fetch all org feeds (requires admin privileges). "My Feeds" returns only your feeds.
  • Refresh ⟳: Re-fetches the feed list for the current scope without re-authenticating.
  • Supported / All: Client-side filter toggle that shows only supported feed types by default, or all feed types including unsupported ones.
  • Feed Type dropdown: Filters feeds by type. Each type has a unique icon prefix and colour (see Feed Type Reference below).
  • Feed dropdown: Select a specific feed to view its details. Unsupported types shown with ⚠ prefix and muted styling.
  • Info panel: Displays the feed's label, ID, type (with coloured icon badge), URL, auth type, format, and schema fields.
  • Apply: Auto-populates the main window's connection mode, host, port, path, TLS, and format from the selected feed. Disabled for unsupported types.
  • Remember me: Persists portal URL and username (not password) across sessions.

Authentication: After applying a feed, the Simulator automatically attaches a Bearer token to gRPC metadata, HTTP headers, and WebSocket upgrade headers. Token is proactively refreshed at 80% of its lifetime.

Hold the pointer nearly stationary over a control to show a custom, theme-aware tooltip. Ordinary movement, clicking, typing, scrolling, dragging, keyboard focus, and modal dialogs suppress visual tooltips so they do not interrupt the task. Focused controls still expose the same details to assistive technology.

Command Line Interface Dialog

The interactive command-line reference now lives in its own Command Line Interface dialog, separate from this product Help dialog.

  • Open it from the keyboard: Press F3 from the main window.
  • Open it from the menu: Use Help → Command Line Interface.
  • Open it from the context menu: Right-click in the main window and choose Command Line Interface.
  • Use it for automation help: Browse searchable and sortable parameters, supported values, defaults, examples, and headless notes.
  • Filter and refine: Use quick category chips, active filter pills, and sticky sortable columns to narrow the parameter table.
  • Copy or export: Copy example commands or export the currently visible rows as TSV, CSV, Markdown, or JSON.
  • Keyboard shortcuts: In that dialog, use Ctrl/Cmd + F or / to focus the filter, and Escape to close it.
