On this page

    Replay a data file

    ArcGIS Velocity Simulator publishes rows from a CSV or text file over TCP, UDP, HTTP/HTTPS, WebSocket, gRPC, or XMPP. Use it to test ArcGIS Velocity feeds, ArcGIS GeoEvent Server connectors, and compatible services.

    1. Select a file, then select a Preset for a paired local Simulator and Logger test or choose a connection type.
    2. Confirm the host, port, rate, and protocol-specific values in Settings.
    3. Select Connect, then Play to publish the selected file.

    A preset only fills editable fields. It never connects, never starts playback, never selects a file, never saves a password, and never changes startup defaults. Selecting Custom preserves current values; editing a populated preset changes its label to Custom (modified).

    Use Protocol Settings

    Select Settings, or press Cmd/Ctrl + Shift + P, to open the resizable Protocol Settings window. The compact connection row holds preset, connection type, host, port, replay controls, and connection actions.

    • Basics contains TCP and UDP payload format, HTTP and WebSocket format and path, gRPC serialization and RPC type, and XMPP conversation or account values.
    • Security contains TLS or STARTTLS policy, certificate paths, certificate verification, and remote binding where applicable.
    • Advanced contains TCP and UDP CSV schema and geometry, HTTP GET polling, WebSocket subscription and first-message handling, and XMPP timing values.
    • Summary provides the effective connection and warnings. Secrets are shown only as Set (hidden), Empty, or Not set.

    Edits apply to the next connection. Done and Escape keep them; Revert changes restores the values present when the window opened; Reset to preset reapplies a modified preset. While connected, Settings opens read-only in Summary mode.

    See the connection summary and Protocol Settings guide for the complete behavior.

    Format TCP and UDP payloads

    TCP and UDP keep their Address family selectors in Protocol Settings, under Basics. TCP defaults to Auto, preserving system address selection; UDP defaults to IPv4. Explicit IPv4 or IPv6 resolves hostnames only in that family, and explicit IPv6 listeners accept IPv6 only. Use ::1 for local IPv6; enter the port separately. A selector change never rewrites Host or changes a local preset's 127.0.0.1 default.

    The source remains CSV-first. Delimited (CSV), the default, preserves each complete logical CSV record. JSON converts it to one object, GeoJSON to one Feature, and Esri JSON to one feature. Quoted fields, escaped quotes, and embedded CSV newlines remain within the same logical record. XML remains an HTTP and WebSocket choice; it is not available for TCP or UDP.

    CSV header row is off by default. When enabled for a structured format, the first logical record supplies field names and is not sent. Otherwise, fields receive deterministic names such as field_1. Set both X field and Y field for point geometry, or leave both empty for null or absent geometry. WKID defaults to 4326; GeoJSON requires 4326, while Esri JSON includes the configured WKID.

    TCP terminates logical payloads with a newline, but byte-stream reads may fragment or combine them. UDP sends exactly one complete UTF-8 payload per datagram, rejects payloads over 65,507 bytes before send, and never reassembles across datagrams. Practical UDP limits can be lower.

    Configure TLS safely

    Client certificate verification is enabled by default whenever TLS or STARTTLS applies. The explicit Allow unverified option accepts an unverified server certificate for any host; traffic remains encrypted, but the server identity is not checked. Keep it off except for a deliberate test such as a local automatic self-signed certificate.

    For HTTP, WebSocket, and gRPC, client mode uses the OS certificate store unless a custom CA certificate is supplied. Server-mode TLS requires a certificate and key. An XMPP server uses an automatic self-signed pair only when both certificate and key are empty; configuring only one is an error.

    See the TLS guide for certificate, trust-store, and mutual TLS guidance.

    Publish with XMPP

    XMPP uses port 5222, Direct conversation, and Required STARTTLS by default. The Simulator defaults to client role when XMPP is selected. In client mode, configure the XMPP domain, account, and up to 20 destination JIDs. In server mode, the Simulator publishes to every signed-in account or to the room it occupies.

    • Direct publishes one-to-one chat messages. Room (MUC) publishes groupchat messages and requires a room and nickname.
    • Client passwords and server external-account passwords may be intentionally empty for a local test, but the associated username remains required.
    • Connect and reply timeouts default to 30000 ms and 15000 ms. Client ping and reconnect intervals default to 60000 ms. Each must be a positive whole number.
    • For a local paired test, select Local XMPP — Logger Server / Simulator Client in both applications. Connect the Logger first, then connect and start playback here.

    Use the XMPP guide for full setup, conversation semantics, and troubleshooting.

    Connect to ArcGIS Velocity

    Select the ArcGIS Velocity sign-in control to browse feeds and apply supported connection settings. The shared Velocity endpoint section offers Automatic discovery or a Custom public URL. Detect again previews discovery; Apply URL validates the selected address with the current Portal session and reloads feeds.

    If the Portal has multiple Velocity servers, All Velocity servers aggregates their feeds by default. Each result identifies its source server, and partial failures do not hide healthy results. Select one Server to edit its custom URL; each override belongs only to that Portal and server.

    Pending endpoint edits block feed application, and changing the Portal requires sign-in again. While disconnected, Apply fills validated connection settings without connecting or starting playback. TCP, GET-based HTTP Poller, and WebSocket feeds select the complementary Simulator server or client role. Both UDP feed types receive datagrams and select Simulator UDP Client with the advertised data host and port, never the management URL. Missing or wildcard UDP hosts require manual configuration with a reachable data host and matching address family. Velocity UDP Server feeds and TCP Server feeds and outputs bind IPv4 only; Apply rejects IPv6 for these connectors. Other socket connectors can use advertised IPv6 literals when the deployment and network support them. Feeds that require an unimplemented broker or provider protocol remain visible under All. Stored passwords and feed secrets are never recovered.

    UDP has no registration or handshake. The paired Logger UDP client's registration datagram is a custom application convention used only with a generic Simulator UDP Server; it is renewed every 30 seconds by default while connected so a restarted Simulator can relearn the recipient. The Logger controls the renewal interval. The marker is excluded from payload records and does not acknowledge delivery or confirm liveness. Velocity feeds and Simulator UDP clients do not send registration or renewal datagrams. Append LF defaults to on for delimited UDP publishing, including local presets, for compatibility with Velocity sampling and newline-framed receivers. It preserves an existing trailing LF, does not change structured payloads, and counts the LF toward the datagram byte limit. An explicit udpAppendNewline=false keeps original datagram bytes; a missing saved setting uses the enabled default. The Logger preserves incoming bytes and has no sending Append LF option.

    After you apply a supported feed, the Simulator can attach its token to supported gRPC metadata, HTTP headers, and WebSocket upgrade headers. The token is refreshed before it expires and is never displayed in the interface.

    See the ArcGIS Velocity sign-in guide for controls, exact tooltips, feed selection, and authentication, and the Velocity REST API guide for public addresses, discovery, and resource paths.

    Control playback

    Select Play to replay the selected file at the configured lines and interval rate; use pause, stop, and loop controls to manage a running replay. File selection and playback actions remain in the main window so they stay available while protocol-specific settings are organized separately.

    Gesture and voice controls can provide hands-free connection and playback actions when their respective support is enabled. See the developer guide for local setup and troubleshooting.

    Use the command-line reference

    Press F3, select Help → Command Line Interface, or use the toolbar action to open the dedicated Command Line Interface dialog. It supports text search, quick filters, sortable columns, visible-row copy/export, and example commands.

    The terminal equivalents are npm run help:cli, npm run help:cli:wide, and npm run help:cli:narrow. See the command-line reference for every option and the configuration guide for saved settings.
